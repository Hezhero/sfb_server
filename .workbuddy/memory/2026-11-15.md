## 大淘客应用凭据配置 + 可用性测试

**配置**（凭据来源：用户提供的应用详情页截图，6 倍放大逐字符读取）：
- `dataoke.key` / `secret`：写入 `mshop-app` 与 `mshop-admin` 的 `application-dev.yml`（明文）
- prod 两份改为 `${DATAOKE_KEY:}` / `${DATAOKE_SECRET:}` 环境变量占位
- `tb.pid.channelPid` 四份 yml 全部更新为新 PID
- pyyaml 解析通过；`mvn -pl mshop-admin,mshop-app -am compile -o` → BUILD SUCCESS

**测试结果：不通**。`GET https://openapi.dataoke.com/api/goods/get-goods-list` 返回 HTTP 439 `{"message":"appkey不存在.."}`。

**已排除的原因**：
1. 网关地址错误 → 官方文档 `api-d.html?id=7` 确认仍是 `openapi.dataoke.com/api`，调用示例 `ApiClient.sendReq(url, appSecret, paraMap)` 与项目实现一致
2. 签名算法错误 → 按项目 `SignMD5Util` 逻辑（TreeMap 有序拼接 + `&key=` + MD5 大写）复现；另用新版 `signRan`+`nonce`+`timer` 复测，错误相同
3. 单字符误读 → 枚举 8 个易混字符变体（0/O、8/B、增减字符），全部返回同一错误
4. 应用同步延迟 → 间隔 5 分钟重测，仍失败

**根因已定位并解决（用户提供精确文本后）**：6 倍放大仍把 APP_KEY 多读了一个 `cf`。
- 错误值 `6af7cfcfec088d`（14 位）
- **正确值 `6af7fcfec088d`（13 位）**
- 印证：项目原占位符 `xxxxxxeb094a5` 正好 13 位

已修正两份 dev yml 并复测，**链路全部打通**：

| 接口 | 结果 |
|---|---|
| 商品列表（旧签名 sign） | ✅ HTTP 200 / code=0 |
| 商品列表（新验签 signRan+nonce+timer） | ✅ code=0，两种都支持 |
| 商品搜索（中文"抽纸"） | ✅ code=0，URL 编码处理正确 |
| 高效转链（`goodsId`=新加密串 + 新 PID） | ✅ code=0，返回真实 couponClickUrl |
| 订单查询 `get-order-details` | ⚠️ code=0 但 data=null，`获取阿里妈妈key失败` |

**两个重要发现**：
1. **数字 ID 转链已被联盟禁用**：`goodsId=530885058847` → code=400「根据联盟政策要求，不允许数字id转链，请使用新商品id」。参数名必须是 `goodsId`（写成 `goodsSign` 报"商品ID异常"），值必须是商品列表/解析返回的加密串。项目现有 `goodsWord(goodsId,...)` 传的正是该加密串，方向正确。
2. **订单采集卡在淘宝联盟授权**：大淘客订单接口需绑定阿里妈妈 AppKey。项目 `tb.appKey` 仍是占位符 `xxxx3230`，所以订单同步跑不起来。商品/转链不受影响。

**prod 已用环境变量隔离**：`DATAOKE_KEY` / `DATAOKE_SECRET`，四份 yml 的 PID 统一为 `mm_31334595_3451950111_116349150207`。pyyaml 解析通过，mvn compile BUILD SUCCESS。

**安全**：dev 两份 yml 被 git 跟踪，凭据会随 commit 进仓库，push 前需处理。
