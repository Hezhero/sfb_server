# 三平台可用性评估报告

> 评估对象：大淘客、好单库、穿山甲（`csj` 激励视频 + `csj-ecom` 电商联盟）
> 评估日期：2026-11-16
> 评估方式：源码逐行审查 + 官方 API 文档核对 + 配置文件实证
> 评估范围：`mshop-app` / `mshop-admin` / `mshop-store` 后端链路，以及 `app`（Flutter）端集成现状

## 零、结论摘要

### 0.1 三个平台一句话结论

| 平台 | 代码完整度 | dev 可用性 | prod 可用性 | 核心问题 |
| --- | --- | --- | --- | --- |
| **大淘客** | 高（42 枚举 / 实际调用 26） | ✅ 可用 | ⚠️ 依赖环境变量 | 缺会员备案；商品库不同步；无超时无重试 |
| **好单库** | 中（47 常量登记但零调用） | ⚠️ 部分可用 | ⚠️ 依赖环境变量 | VIP 密钥是占位符；死代码多；订单通道单点依赖大淘客 |
| **穿山甲 `csj`** | 高（后端 + APP 闭环） | 🚫 关闭 | 🚫 关闭 | `enabled=false` + appId/广告位双空；缺 S2S 防伪 |
| **穿山甲 `csj-ecom`** | 中（服务端骨架完备） | 🚫 关闭 | 🚫 关闭 | 开关关闭 + 无 API 权限 + 双端零集成 |

| 初版结论 | 实际状态 | 证据 |
| --- | --- | --- |
| ~~美团有转链无订单~~ | **已完整实现** | `OrderMtCPSCollectionTask` + `OrderTask.saveMtCPS()` + `MailvorMtOrder` + `MailvorMtOrderService`，走独立 `meituanService` 通道，非好单库 |

### 1.4 签名与请求

**算法正确**：参数按 key 升序 → 拼 `k=v&` → 末尾拼 `&key=secret` → MD5 → 全大写。使用 `TreeMap` 天然有序，并显式规避了双重 URL 编码（`DataokeApiClient.java:28-32` 注释说明）。

**发现的 bug**：

| # | 问题 | 位置 |
| --- | --- | --- |
| B1 | `appkey` 与 `appKey` 重复出现，同一请求带两个大小写不同的键且都参与加签 | `DataokeService.java:361,377,386` + `DataokeApiClient.java:39` |
| B2 | `sendReq` 直接修改调用方传入的 map，map 复用会导致二次加签失败 | `DataokeApiClient.java:31,38,39` |
| B3 | 前置校验返回**中文句子而非 JSON**，调用方 `JSON.parseObject` 会抛 `JSONException` | `DataokeApiClient.java:18-26` |
| B4 | `appKey` 空值不校验，key 为空照发 | `DataokeApiClient.java:17-26` |
| B5 | 硬编码第三方 appKey：`612bcfe884763`、`aqoadw` | `DataokeCmsController.java:176,254`、`TkConstants.java:23` |
| B7 | `cid`/`pageId` 为 null 时 NPE（控制器只拦了 `==0`，没拦 null） | `DataokeService.java:374-375,384-385,439` |

### 1.5 错误处理

| 项 | 状态 | 说明 |
| --- | --- | --- |
| **HTTP 超时** | ❌ **缺失** | 主链路用 hutool 静态 `HttpUtil.get()`，全仓无 `HttpGlobalConfig.setTimeout`。上游挂起会拖死 Tomcat 线程 |
| 重试/退避/熔断 | ❌ 缺失 | `tk/`、`dataoke/` 下零实现 |
| 限流/429/配额 | ❌ 缺失 | 无任何分支 |
| 业务错误码校验 | ⚠️ 部分 | `/tao/*` 全系列不校验，JD/PDD/VIP 校验 |
| 异常处理 | ⚠️ 部分 | 6 处 `e.printStackTrace() + return null` 吞异常 |
| 敏感信息落日志 | ⚠️ 风险 | 订单链路 `log.warn` 打印**完整响应体**，含用户 uid |

> `DataokeConfig.requestFactory()` 设的 15s/15s 超时只作用于 `RestTemplate`，而 `RestTemplate` 只被 CMS 直连类接口使用，**dataoke 主链路不受其保护**。

### 3.5 两处必须修正的项目文档错误

**① `100011 暂无业务权限` 无官方出处**

**② `csj-ecom.adzoneId` 是淘系遗留的无效配置**

`CsjEcomConfig.java:46-47` 声明了该字段，但**全项目零读取**（`getAdzoneId()` 无调用点）。这是从淘宝联盟（`MailvorTbOrder.adzoneId`）惯性抄过来的字段，应删除以免误导运维以为要填。

| **京东搜索**（旧路径 `jd_goods_search`） | `haodanku.key` | 若官方要求京东权限 → 失效 | 中 |
| **`/ku/shortLink` 短链** | `haodanku.vip.appId` + `vip.appSecret` | **当前是占位符 `xxxxxx`** → 必然失败 | 中 |
| **剪贴板识别兜底**（`TkService:239`） | 同上 VIP 密钥 | **静默失效**，仅 `log.warn`，用户无感知 | 中——主流程走大淘客，不受影响 |
| **拼多多转链/凑单/种草机**（v2 接口） | `haodanku.key` + 硬编码 `code` | 若 v2 接口下线 → 失效 | 低 |

> **关键判定**：好单库 VIP 密钥（占位符）**只影响 2 个功能**，且剪贴板识别有主路径兜底，不影响核心交易。
>
> 而 `kuCid`（数据库配置）和 `waimaiKey` 才是真正的高危项——缺失会导致抖音 CMS 全家桶或外卖链路整段失效。

### 4.3 三平台权限影响汇总

| 平台 | 已配 | 缺什么会失效 | 影响面 |
| --- | --- | --- | --- |
| **大淘客** | ✅ key/secret | 唯品会权限、抖客权限、拼多多权限 | 唯品会/抖音/拼多多**整条平台线失效** |
