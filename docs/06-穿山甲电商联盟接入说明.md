## 一、这次校正改了什么

第一版代码是基于第三方整理文档写的，拿到官方 PDF 后发现**字段名大面积对不上**。以下是实际修正项，这段比后面的说明更值得看：

| 位置 | 第一版（错） | 官方（对） |
| --- | --- | --- |
| 商品搜索参数 | `keyword` | **`title`** |
| 商品名称字段 | `product_name` | **`title`** |
| 商品主图 | `product_img` | **`cover`** |
| 佣金比例 | `commission_rate` | **`cos_ratio`**（百分比 ×100，1% 返回 100） |
| 佣金金额 | `commission` | **`cos_fee`**（分） |
| 商品链接 | — | **`detail_url`** |
| 转链必传 | 无 | **`product_ext`**（来自搜索结果的 `ext`，不传会降成功率） |
| 转链归因字段 | `custom_info` | **`external_info`**（≤40 字符，只允许字母数字下划线） |
| 转链返回 | `click_url` / `tpwd` / `deep_link` | **`dy_deeplink`** / **`dy_password`** / `dy_qr_code` / `dy_sharelink` |
| 订单分页 | `page` + `page_size` | **`cursor` + `size`**（size 最大 50，cursor 首次传 `"0"`） |
| 订单时间参数 | `"yyyy-MM-dd HH:mm:ss"` 字符串 | **秒级时间戳**（int），跨度 ≤90 天 |
| 订单必填 | 无 | **`order_type`**（1商品/2直播/3活动） |
| 订单佣金 | `commission` | **`estimated_commission`** / `ads_real_commission` |

**这些错误如果没被校正，上线后表现为"接口一直报签名错或参数错"，很难定位**——因为签名算法本身是对的，坏在字段名上。

## 二、这是什么

穿山甲电商联盟不是新电商平台，是**抖音电商 CPS 分销**（原名「乘风计划」/「抖客」），与项目已有的抖音模块是同一货源、不同通道。

| 对比 | 现有通道（大淘客/好单库） | 穿山甲电商联盟 |
| --- | --- | --- |
| 数据来源 | 第三方聚合转发 | 字节官方 CPS 直连 |
| 需要资质 | 注册账号即可 | 企业/个体户 + 签合同 + 合规考试 + 流量备案 |
| 佣金 | 经第三方抽一道 | 直接结算给媒体 |

## 三、准入门槛（决定能否跑通）

### 3.1 主体资质

- 中国大陆**企业法人**或**个体工商户**（个人不行）
- 经营范围含广告、推广、信息技术服务、电子商务等
- 法人 + 经办人实名认证，经办人需授权委托书
- 企业对公账户（平台打小额验证款）

### 3.2 接口权限

| 接口 | 门槛 | 未开通返回 |
| --- | --- | --- |
| `/order/search` | 实名 + 角色绑定 | — |
| `/product/search`、`/product/detail`、`/product/category`、`/product/link` | **必须完成流量备案** | `{"code":100011,"desc":"暂无业务权限"}` |

备案两种方式：
1. **App 已上架**：应用市场下载页链接 + 包名 + 线上运行截图
2. **未上架**：签《媒体流量备案登记表》并提交流量说明（推广场景、DAU/MAU 预估、跳转抖音链路）

**《媒体流量备案登记表》在哪填**（官方 26632 / 28560 原文路径）：

1. 登录穿山甲媒体平台
2. 左侧菜单 **「屏蔽与合规」→「问询记录」**
3. 找到待处理的流量备案条目，点 **「立即处理」**
4. 按页面提示填写《备案登记表》，**上传附件**，提交送审

> 前置条件：这一步只有在**完成合同签订 + 合规考试**之后才会出现。没签合同看不到「屏蔽与合规」菜单，这是最常见的"找不到入口"。

**字段级入口（备选）**：部分账号版本在「电商联盟 → 账户管理 → 接入管理」选中具体应用后，也有单独的"提交流量备案材料"入口。两处提交的是同一套材料，以「屏蔽与合规 → 问询记录」为准。

**找不到入口时的兜底**：媒体平台右下角「穿小甲」→ 在线客服 → 自助建单，直接问"电商联盟流量备案表在哪填"。这个渠道比翻文档快。

### 3.3 后续考核

V1~V4 等级体系，考核月 GMV、退款率（≤40%）、推广管理分（≥10），不达标可能取消 API 权限。

### 3.4 没有 App 怎么对接（常见情况）

**可以对接，官方明确允许用「测试应用」占位。**

官方原文（媒体推广操作手册 28271、如何申请接入 26632）：

> 选择「账户管理」-「接入管理」，完成应用创建（"添加应用"相当于创建推广位，**没有 APP 的推广渠道，可以填写一个"测试应用"填入**）。
>
> 在穿山甲电商联盟业务中，**可添加测试应用作为推广位，测试应用可正常结算**。

三种载体可选，按落地速度排序：

| 载体 | 适用 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **测试应用** | 还没有任何线上产品，或 App 在开发中 | 立刻能创建，无需商店链接 | 备案时流量说明要为"测试"找到合理解释 |
| **H5 / 公众号 / 社群导购** | 有微信群、公众号、落地页 | 备案材料好写（截图 + 流量说明） | 项目当前没有 H5 端，需另做 |
| **已上架 App** | 正式运营 | 权限最稳，无争议 | 要先上架，周期最长 |

> ⚠️ 注意区分两个"测试"：
> - **测试应用（电商联盟）**：官方说**可正常结算佣金**，这是推荐做法。
> - **测试代码位（广告变现）**：官方说**不计收益**。
>
> 两者是不同业务，别被"测试不结算"那句话误导。

### 3.5 真正的卡点不是 App，是 API 权限考核

这是最容易被忽略的一环。开通电商联盟 **API 推广权限**需要同时满足（官方 26632，2025-11-18 起）：

| 条件 | 要求 |
| --- | --- |
| 推广管理分 | ≥ 10 |
| 退款率 | ≤ 40% |
| **开通首月日均付款佣金** | **> 1000 元** |
| **次月日均付款佣金** | **> 2000 元** |

也就是说：**没有量就拿不到 API 权限，拿不到 API 又不好做量**——典型的鸡生蛋。

**破局路径**（重要）：

1. **先用平台自带工具转链，不写代码**
   - PC 端：`csjplatform.com/union/media/union` → 选品广场 / 转链工具
   - 手机端：官方「好货有佣」App
   - 手动把商品转成口令/链接，发到社群或公众号做成交
2. 累计到首月日均佣金 > 1000 元
3. 这时再申请 API 权限，代码才真正用得上
4. 权限开通后，用 `csjEcomOrderCollectionTask` 采集订单，替代手工对账

**结论**：没有 App 不影响入驻和结算，只影响"什么时候能用 API"。在拿到 API 权限前，本项目这套代码处于"已就绪但未启用"状态，这是正常的。

### 3.6 没达到考核标准会怎样

**结论：不会失去推广资格，失去的只是"用 API 自动化"这件事。**

穿山甲把"能不能做"和"能不能用 API"分成两层，很多人混为一谈：

| 层级 | 门槛 | 没达标的结果 |
| --- | --- | --- |
| **入驻 / 推广资格** | 企业或个体户 + 签合同 + 合规考试 + 流量备案 | 不会因为佣金量不达标被取消 |
| **API 调用权限** | 推广管理分 ≥10、退款率 ≤40%、首月日均佣金 >1000、次月 >2000 | **取消 API 权限**，退回平台工具手动转链 |
| **V1~V4 等级权益** | 月 GMV 门槛（V1 约 2k/日） | 降级，权益缩水（如中高佣货盘配额） |

官方原文只说「取消 **API 推广权限**」，没说取消合作。所以最坏情况是：

- 转链、推广、成交、佣金结算 —— **照常**
- 只是不能再调接口，回到「选品广场 / 转链工具 / 好货有佣 App」手工操作

**对规模的影响**：手工一天转几十个链接是极限，做不了商品列表页、自动转链、订单自动对账。所以"没达标"不致命，但确实卡住了规模化。

**对已有佣金的影响**：API 权限只决定"怎么取数据"，不参与佣金结算规则。已经产生的订单按《结算规则》走（确认收货 15 天后标记可结算，次月第 10 个工作日生成结算单）。

## 四、签名算法（已实测比对）

```java
String signStr = String.format("app_id=%s&data=%s&req_id=%s&timestamp=%d%s",
        appId, data, reqId, timestamp, secureKey);
String sign = MD5(signStr);   // 32 位小写
```

**四个要点**：

1. `version`、`sign_type`、`sign` 自身**不参与加签**（拼进去报 `100004`）
2. `data` 必须是紧凑 JSON，且**签名与发送复用同一个字符串**
3. `timestamp` 是**秒级**（`System.currentTimeMillis() / 1000`）
4. **时间差必须 < 10 分钟**（否则 `100005`）——服务器要做 NTP 对时

实测记录：

```
输入: appId=123456, data={"page":1,"page_size":20}, reqId=abc123def,
      ts=1700000000, key=test_secure_key_9f8e7d
输出: e95395e1a59ad40875e305cf9ab1d82d
对照: Python hashlib.md5 独立计算结果完全一致 ✅
```

## 五、接口对照

### 5.1 商品列表 `/product/search`

请求 `data`：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `page` | int | 是 | 从 1 开始 |
| `page_size` | int | 是 | **1~20**，超限报 100002 |
| `title` | string | 否 | 商品关键词 |
| `first_cids` / `second_cids` / `third_cids` | int array | 否 | 类目筛选 |
| `price_min` / `price_max` | int | 否 | 单位分 |
| `sell_num_min` / `sell_num_max` | int | 否 | 历史销量 |
| `search_type` | int | 否 | 0默认 1销量 2价格 3佣金 4佣金比例 |
| `order_type` | int | 否 | 0升序 1降序 |
| `cos_fee_min/max`、`cos_ratio_min/max` | int | 否 | 佣金筛选 |
| `activity_id` | int | 否 | 1 超值购，0 全量 |

响应 `data`：

```json
{
  "total": 1234,
  "products": [
    {
      "product_id": 3513960257372205206,

      "cos_ratio": 2000,
      "cos_fee": 1198,
      "sales": 3200,

      "in_stock": true,
      "shop_id": 1,
      "shop_name": "店铺"
    }
  ]

```

> `total` 超过 2000 只返回前 2000 条。

### 5.2 商品转链 `/product/link`

请求 `data`：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `product_url` | string | 是 | 与搜索返回的 `detail_url` 一致 |
| `product_ext` | string | 否 | 搜索返回的 `ext`，**尽量填** |
| `external_info` | string | 否 | 归因信息，只允许字母数字下划线，≤40 |
| `share_type` | int array | 否 | 1deeplink 2二维码 3口令 4zlink 5sharelink，默认只有 1 |
| `platform` | int | 否 | 0抖音 1极速版 |
| `use_coupon` | bool | 否 | 是否返回券后价链接 |

响应 `data`：

| 字段 | 说明 |
| --- | --- |
| `dy_deeplink` | 抖音 deeplink（share_type 含 1） |
| `dy_qr_code` | 二维码对象（含 url/width/height，含 2） |
| `dy_password` | 抖音口令（含 3） |
| `dy_zlink` | zlink（含 4） |
| `dy_sharelink` | sharelink（含 5） |
| `coupon_link` | 券后价推广链接 |

> 代码默认 `share_type=[1,3]`（deeplink + 口令），覆盖 APP 内唤起和复制分享两种场景。二维码生成慢，不需要别传 2。

### 5.3 商品详情 `/product/detail`

请求：`{"product_ids": [123, 456]}`（数组）

响应比列表多：`imgs`、`comment_score`、`comment_num`、`order_num`、`view_num`、`kol_num`、`brand_info`、`tags`、`available_coupons`、`shop_total_score`。

> 官方提醒：`product_id` 是 long，注意精度丢失，用 int64。

### 5.4 商品类目 `/product/category`

请求：`{"parent_id": 0}`（0 查一级）

响应：`{"total": n, "category_list": [{"id":1,"name":"女装","level":1}]}`

## 七、错误码（官方）

| code | 含义 | 处理 |
| --- | --- | --- |
| 100002 | 请求格式出错 | 看 desc，常是 page_size 超限或参数缺失 |
| 100003 | sign_type 不是 MD5 | 固定 `"MD5"` |
| 100004 | 签名校验错误 | 检查 secureKey、role_id、加签字段集合 |
| 100005 | 时间校验错误 | **服务器与穿山甲时间差 > 10 分钟**，需 NTP 对时 |
| 100006 | 应用 id 不合法 | app_id 未接入电商联盟，或接入有 15 分钟延迟 |
| 100007 | 接口禁止访问 | — |
| 100011 | 暂无业务权限 | 未完成流量备案 |
| 200001 | 未搜索出结果 | 商品/直播列表的空结果，非错误 |
| 500000 | 服务端内部错误 | 带 req_id 找穿山甲客服 |

代码里已把这些翻译成中文提示（`CsjEcomClient.describeError`），原始 desc 附在后面。

## 八、配置与部署

```yaml
csj-ecom:
  enabled: false
  appId: ""
  secureKey: ""          # 后台获取，对应 role_id 必须与主账户 id 一致
  adzoneId: ""
  baseUrl: https://ecom.pangolin-sdk-toutiao.com
  pageSize: 20
```

**4 份 yml 都要配**（admin 与 app 各 dev/prod）：订单采集跑在 `mshop-admin`，只配 app 会导致采集拿不到配置。

### 8.1 密钥管理（重要）

`secureKey` 等同于签名私钥，泄露即可被冒用调用接口。当前安排：

| 环境 | 存放方式 | 原因 |
| --- | --- | --- |
| dev | yml 明文 | 本地开发便利 |
| prod | `${CSJ_ECOM_SECURE_KEY:}` 环境变量 | 不落配置、不落仓库 |

**生产启动方式**：

```bash
export CSJ_ECOM_SECURE_KEY='你的 secureKey'
java -jar mshop-app.jar --spring.profiles.active=prod
```

**dev.yml 的风险**：该文件**已被 git 跟踪**，明文密钥会随 commit 进入仓库历史。push 前务必处理，两种做法：

1. 提交前把该行改回 `secureKey: ""`，本地用环境变量或 IDE 配置注入（推荐）
2. 用 git 的 skip-worktree 标记本地忽略修改：
   ```bash
   git update-index --skip-worktree mshop-app/src/main/resources/config/application-dev.yml
   ```

**如果密钥已经外泄**（比如进了公开仓库、发到了聊天工具），必须在穿山甲后台重置 secureKey。判断依据很简单：拿到它的人可以构造合法签名调用你账号下的所有接口。

**启动自检**：服务启动时 `CsjEcomConfig` 会打一条日志，可直接确认配置是否生效：

```

```

若看到 `未启用` 或 `配置不完整`，说明 yml 没被读到或者缺项，不用去猜。

返回：

```json
{"deepLink":"snssdk1128://...","password":"8.88 d@u.cl ...",
```
