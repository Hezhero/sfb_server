# 全平台 CPS 转链分销指南（零考核版）

> 编写时间：2026-11-13
> 目标：**只做转链分销拿佣金，不碰任何 API 考核**
> 依据：`syh_server` / `syh` 源码实证 + 各平台公开规则
> 适用：个体工商户、小微企业、个人

---

## 一、结论：7 个平台都能做，而且都不用参加考核

先纠正一个普遍误解——**"考核"和"能不能做"没有关系**。

| 你以为的 | 实际的 |
| --- | --- |
| 要接 API 才能做 CPS | 手工转链就能拿佣金，一分不少 |
| 要通过考核才有资格推广 | 考核只卡"API 高级权限"，不卡推广资格 |
| 不接 API 就白搭这个系统 | 有大淘客这条路，一个账号覆盖 5 个平台 |

| 平台 | 最低门槛 | 需要考核吗 | 能进系统吗 |
| --- | --- | --- | --- |
| 拼多多 | 身份证 | ❌ | ✅ 官方 API 无考核 |
| 京东 | 身份证 | ❌ | ✅ 官方 API 无考核 |
| 淘宝 | 身份证 | ⚠️ 仅订单 API | ✅ 转链可；订单走大淘客 |
| 唯品会 | 身份证 | ❌ | ✅ 大淘客 |
| 抖音 | 身份证 | ❌ | ✅ 大淘客 |
| 饿了么 | 身份证 | ❌ | ✅ 好单库 |
| 美团 | **营业执照** | ❌ | ✅ 官方 API 无考核 |

**核心结论：唯一有考核的是抖音官方的穿山甲电商联盟 API（首月日均佣金 >1000 元）。绕开它——用大淘客的抖音通道，就没有任何考核。**

## 二、三个概念别搞混

这是所有新手卡住的地方：

| 概念 | 是什么 | 必须做吗 |
| --- | --- | --- |
| **入驻 / 注册** | 注册账号、实名认证 | ✅ 必须 |
| **备案** | 媒体备案、推广位备案、流量备案 | ✅ 必须（否则转链无效或佣金失效） |
| **考核** | 对 API 调用权限的佣金量要求 | ❌ **可以完全不做** |

**备案 ≠ 考核**。备案是"证明你有流量、链路合规"，填表就行；考核是"要求你做出多少佣金才给你 API"。

我们这份指南：**做入驻、做备案、不碰考核**。

## 三、三条路径，按技术投入排序

| 路径 | 技术投入 | 覆盖平台 | 数据进系统 | 适合 |
| --- | --- | --- | --- | --- |
| **A. 纯手工** | 0 | 7 个全支持 | ❌ 只能人工对账 | 先验证能不能卖出去 |
| **B. 聚合 API** | 低（配 key） | 5-6 个 | ✅ 全自动 | **推荐** |
| **C. 官方 API** | 中（逐个申请） | 7 个 | ✅ 全自动 | 后期优化佣金率 |

**推荐走 B**：注册大淘客 + 好单库，两个账号覆盖除美团外的所有平台，项目代码已集成，填 key 即可。

### 3.1 直连官方 vs 走聚合：不是一个二选一的问题

关键要先搞清一件事——**佣金最终进谁的口袋**。这取决于平台是否允许你用自己的推广位（PID）。

| 平台 | 走聚合时用自己的 PID？ | 佣金归属 | 聚合抽不抽 |
| --- | --- | --- | --- |
| 淘宝 | ✅ 代码传 `tbConfig.getChannelPid()` | **自己的联盟账户** | **不抽**（聚合只做接口转发） |
| 京东 | ✅ 传自己的 `siteId` | **自己的联盟账户** | 不抽 |
| 拼多多 | ✅ 传自己的 PID | **自己的多多进宝账户** | 不抽 |
| 美团 | 走官方，本来就不经聚合 | 自己的账户 | 不抽 |
| **抖音** | ❌ 只能用聚合的媒体主体 | 聚合账户 → 再分给你 | **抽成** |
| **唯品会** | ❌ 同上 | 聚合账户 → 再分给你 | **抽成** |

**为什么会有这个差别**：淘宝/京东/拼多多允许第三方系统带着"你的 PID"去转链，订单归因到你的推广位，平台直接把佣金打给你，聚合服务商碰不到钱。抖音和唯品会的官方媒体身份无法这样透传，只能由聚合服务商作为媒体主体去接，再按协议分给你。

**抽多少**（公开信息，以实际协议为准）：

| 聚合 | 抽成 | 来源可信度 |
| --- | --- | --- |
| 好单库（穿山甲抖客库） | **代扣 7% 税费**，能开专票可退回 | 官方 API 协议原文 |
| 大淘客（抖音/唯品会） | 行业说法 10%-30%，官方未公开精确比例 | 第三方文章，需自行核实 |

**这意味着**：抖音、唯品会这两条线，走聚合必然少赚。等抖音月佣金过 3 万，切穿山甲官方 API 省的抽成足以覆盖开发成本——这就是"有量之后要切官方"的真实原因。

反过来说，**淘宝/京东/拼多多走聚合不吃亏**，只是省了逐个申请 API 的麻烦。这两类要分开看。

### 3.2 多维度对比

| 维度 | 直连官方 | 走聚合（大淘客/好单库） |
| --- | --- | --- |
| **佣金** | 100%（只扣平台自身技术服务费） | 淘宝/京东/拼多多不抽；抖音/唯品会被抽 7%-30% |
| **准入门槛** | 逐个平台申请，淘宝订单 API 有邀约制 | 一次注册，1-3 天审核 |
| **覆盖平台** | 7 个（抖音需考核） | 6 个（美团除外） |
| **字段完整度** | 全（官方原始字段） | 有裁剪，部分字段缺失或延迟 |
| **QPS** | 按账号等级，通常更高 | 按套餐，免费额度有限 |
| **稳定性** | 官方 SLA | 依赖第三方，可能因政策调整中断 |
| **结算** | 平台直接打款给你 | 淘宝/京东/拼多多仍直连；抖音/唯品会经聚合转 |
| **发票** | 与平台直接对接 | 抖音/唯品会需与聚合结算，可能被代扣税费 |
| **技术成本** | 7 套 SDK + 7 套签名 + 7 套错误码 | 2 套（项目已集成） |
| **数据主权** | 完全自有 | 商品/订单数据经第三方，注意缓存条款 |
| **政策风险** | 低 | 聚合被平台限制时，全线受影响 |

### 3.3 现有代码是什么策略

`TkService.mixParse()` 的实际路由：

```
识别平台 → 淘宝走 dataokeService.goodsParse（传自己的 channelPid）
         → 京东走 kuService.searchJD
         → 拼多多走 dataokeService.goodsListPdd
         → 兜底走 kuService.clipboard
```

也就是**聚合优先**。但 `JdService`、`PddService`、`TkService` 里都有官方 SDK 的实现，想切随时能切——这是这套代码设计得比较好的地方。

### 3.4 什么时候该切官方

| 信号 | 该做什么 |
| --- | --- |
| 抖音月佣金 > 3 万 | 切穿山甲 API，省掉 7%-30% 抽成 |
| 淘宝订单对账太痛苦 | 申请淘宝订单 API（拿不到就继续用聚合） |
| 日订单 > 1000 | 官方 QPS 更高，聚合额度可能不够 |
| 聚合接口频繁报错/字段变更 | 该平台切官方，避免被动 |

**判断标准很简单**：算一下"被抽走的钱"和"接官方 API 的人力成本"，哪个大走哪边。月佣金 5000 以下，被抽 7% 也就 350 块，不值得投入一周开发。

## 四、逐平台：最快拿到推广链接

### 4.1 拼多多（最快，当天能拿链接）

**路径**：<https://jinbao.pinduoduo.com> → 注册"多多进宝推手"

| 步骤 | 说明 |
| --- | --- |
| 1 | 手机号注册，选"我是推手/推广者" |

## 五、技术落地：哪些数据能进系统

`syh_server` 里已实现的通道（代码实证）：

| 平台 | 商品/转链 | 订单 | 代码位置 |
| --- | --- | --- | --- |
| 淘宝 | 官方 `TkService` / 大淘客 `goodsList` | 官方 `TkService` / 大淘客 `queryTBList` | `tk/service/TkService.java` |
| 京东 | 官方 `JdService` / 大淘客 `goodsWordJD` | 官方 `JdOrderCollectionTask` / 大淘客 `queryJdList` | `tk/service/JdService.java` |
| 拼多多 | 官方 `PddService` / 大淘客 `goodsWordPDD` | **官方** `PddService.queryPddOrderList` | `tk/service/PddService.java` |
| 唯品会 | 大淘客 `goodsDetailVIP` / `goodsWordVIP` | 大淘客 `queryVipList` | `DataokeService` |
| 抖音 | 好单库 `dyProductList` / 大淘客 | 大淘客 `queryDyList` | `KuService` / `DataokeService` |
| 饿了么 | 好单库 `eleActivityList` / `eleWord` | 好单库 `eleOrder` | `KuService` |
| 美团 | 官方 `meituan` 配置 | 官方 `OrderMtCPSCollectionTask` | `quartz/task/OrderMtCPS*` |

**关键：大淘客一个账号就能覆盖 5 个平台的订单**（`queryTBList` / `queryJdList` / `queryPddList` / `queryVipList` / `queryDyList`）。

> 注意：项目里**拼多多订单实际走的是官方 SDK**（`PddService.queryPddOrderList`），大淘客的 `queryPddList` 是备用通道。两条都可用，官方那条字段更全。

### 两个账号的配置位置

```yaml
# mshop-app/application-dev.yml（admin 同）
dataoke:            # 覆盖 淘宝/京东/拼多多/唯品会/抖音
  key: 你的大淘客AppKey
  secret: 你的大淘客AppSecret

haodanku:           # 覆盖 抖音生活服务 / 饿了么
  key: 你的好单库Key
```

> 建议 admin 和 app 用**两个不同的大淘客账号**，订单采集耗调用量，别把客户端查询配额挤掉。

### 大淘客的 API 门槛

- 企业或个体户实名后，1-3 个工作日审核
- 基础权限（商品/转链）自动开放
- **没有佣金量考核**
- 订单接口部分需要"先调用转链接口 3 天"才能开通（技术门槛，不是业绩门槛）

> 个人能否通过大淘客 API 审核，公开资料说法不一（有说个人实名即可，有说必须企业）。**有个体户执照最稳**，没有的话先注册试，或问客服。

## 六、佣金怎么结算（零考核也照常拿钱）

| 平台 | 结算条件 | 到账周期 |
| --- | --- | --- |
| 淘宝 | 确认收货 + 无退款 | 次月 20 号左右 |
| 京东 | 确认收货 15 天后 | 每月 10 号左右 |
| 拼多多 | 确认收货满 15 天无退货 | 每月固定周期 |
| 唯品会 | 确认收货无退货 | 月结 |
| 抖音（大淘客） | 平台结算后转 | 次月 |
| 美团 | 订单完成 7 天后转可结算 | 月结 |
| 饿了么 | 同淘宝体系 | 月结 |

**发票问题**：
- 个人结算：平台代扣个税，无需开票
- 企业/个体户结算：需开票（美团必须专票，个体户可税务代开）

**建议**：如果有执照，一开始就用执照主体结算。个人结算个税综合下来不划算，后期转主体还要重走流程。

| 触发条件 | 该做什么 |
