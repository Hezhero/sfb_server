# 三盈会淘客系统（syh_server）部署与配置手册

> 适用版本：`syh_server` 5.1.0（开源版服务端）
> 文档基于源码实测编写，构建命令已在 JDK 17 + Maven 3.9.4 环境下验证通过
> 配套文档：`01-安全与授权评估报告.md`（**上线前务必先看 P0 整改项**）

---

## 一、系统架构

服务端是两个**相互独立的 Spring Boot 进程**，共享同一套 MySQL 与 Redis：

```
                    ┌─────────────────────┐
   管理后台 SPA ───▶ │  mshop-admin :8001  │  /admin   运营管理 API + 定时任务
   (syh_admin)       └──────────┬──────────┘
                                │
                    ┌───────────┴───────────┐
                    │  MySQL (库 mshop)      │
                    │  Redis (db 2)          │
                    └───────────┬───────────┘
                                │
     Flutter APP  ───▶ ┌────────┴──────────┐
                       │  mshop-app :8008  │  /api   客户端 API
                       └───────────────────┘
```

| 服务 | 启动类 | 端口 | 上下文路径 | 对接端 |
| --- | --- | --- | --- | --- |
| 管理服务 | `com.junchen.AdminServer` | 8001 | `/admin` | `syh_admin` 管理后台 |
| APP 服务 | `com.junchen.AppServer` | 8008 | `/api` | `syh` Flutter APP |

**模块依赖关系**（构建时按此顺序）：

```
mshop-db → mshop-system → mshop-log / mshop-tool / mshop-gen
                              ↓
                          mshop-store → mshop-redis / mshop-mp / mshop-shop
                              ↓
                    mshop-admin  /  mshop-app
```

## 二、环境要求

| 组件 | 版本要求 | 说明 |
| --- | --- | --- |
| JDK | **8**（推荐）/ 11 / 17 | 源码 `java.version=17`；实测 JDK 17 编译与打包均通过 |
| Maven | 3.6+ | 需能访问阿里云仓库 |
| MySQL | 5.7+ / 8.0 | 库名 `mshop`，字符集 `utf8mb4` |
| Redis | 5.0+ | 两个服务都用 **db 2**，注意隔离 |
| Nginx | 1.18+ | 反向代理 + 静态资源 |
| 内存 | 建议 4G+ | 单 JVM 建议 `-Xmx1g` 起，定时任务多可加到 2g |
| 磁盘 | 20G+ | 日志 + 上传文件 + 电子合同（如启用） |

> **关于 JDK 版本**：项目 `pom.xml` 声明 `java.version=17`，Spring Boot 2.7.18 官方支持 8~17。如果生产用 JDK 17 最稳；用 JDK 17 也可以，但要注意 Lombok 与 `--add-opens` 相关问题（实测编译期无问题）。

## 三、依赖服务准备

### 3.1 MySQL

```sql
CREATE DATABASE `mshop` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
CREATE USER 'mshop'@'%' IDENTIFIED BY '改成强密码';
GRANT ALL PRIVILEGES ON `mshop`.* TO 'mshop'@'%';
FLUSH PRIVILEGES;
```

**初始化数据**：仓库**不包含** SQL 脚本，需从官方页面获取：

```
https://syh.hzhero.cn/02.开源版本/01.开发文档/10.db-get.html
```

下载后按顺序导入。导入完成后务必核对以下两点：

```sql
-- 1. 定时任务定义表必须有数据，否则订单采集不会跑
SELECT COUNT(*) FROM quartz_job;

-- 2. 系统配置表里要有 API 地址，否则分享海报/二维码地址为空
SELECT * FROM system_config WHERE `key` IN ('api_url','site_url');
```

> **关键**：`quartz_job` 表是任务定义的唯一来源。项目用 Quartz 的 **RAMJobStore**（`QuartzConfig` 里手动 new `SchedulerFactoryBean`，未配 DataSource），启动时 `JobRunner` 会从该表读取 `is_pause=0` 的任务注册进内存。**不需要 QRTZ_\* 系列表**。

### 3.2 Redis

```conf
# redis.conf 关键项
requirepass 改成强密码
maxmemory-policy noeviction    # 不要用 allkeys-lru，会丢 token 和锁
```

```bash
redis-cli -a '密码' ping    # 期望 PONG
```

> 两个服务都连 **database 2**。如果同一台 Redis 上还跑别的系统，务必确认没有 db 2 冲突。

### 3.3 上传目录

```bash
mkdir -p /home/mshop/file /home/mshop/avatar
chown -R 运行用户:运行用户 /home/mshop
```

> **注意源码里的笔误**：`application-prod.yml` 中 `file.avatar` 写的是 `/homemshop/avatar/`（少一个斜杠），会在根目录创建 `/homemshop/avatar`。部署时请统一改成 `/home/mshop/avatar/`。

## 四、配置文件

两个服务各有 3 个配置文件：

```
mshop-admin/src/main/resources/config/
├── application.yml        # 公共配置（端口、context-path、默认 profile）
├── application-dev.yml    # 开发环境
└── application-prod.yml   # 生产环境
mshop-app/src/main/resources/config/
├── application.yml
├── application-dev.yml
└── application-prod.yml
```

### 4.1 默认 profile 是 dev，不是 prod

`application.yml` 里写的是：

```yaml
spring:
  profiles:
    active: dev
```

> 这与 README 里"当前主配置指定了 syhadminprod / syhappprod"的说法**不一致**。实际以代码为准：默认走 `dev`。生产环境请显式指定 `--spring.profiles.active=prod`，或直接改 `application.yml` 里的 `active` 值。

### 4.2 两个服务必须一致的配置

以下配置在 admin 与 app 中**必须完全一致**，否则会出现"后台改了、APP 读不到"的诡异问题：

| 配置 | 说明 |
| --- | --- |
| `spring.datasource.druid.url/username/password` | 同一套库 |
| `spring.redis.host/port/password/database` | 同一个 db（2） |
| `tb.*` / `pdd.*` / `jd.*` / `dataoke.*` / `haodanku.*` | 联盟凭据与 PID |

> 官方注释建议大淘客 key 在 admin 与 app 中用**不同的账号**（`dataoke` 配置上方注释：「最好和 mshop-app 中的不一致，防止订单采集耗空调用量」）。这是合理的——采集消耗调用量，查询也消耗，分账号能避免互相挤占。

### 4.3 配置项完整清单

#### 必填（不填服务起不来或核心功能不可用）

| 配置项 | 示例 | 说明 |
| --- | --- | --- |
| `spring.datasource.druid.url` | `jdbc:mysql://127.0.0.1:3306/mshop?...` | 保留 `characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai` |
| `spring.datasource.druid.username` | `mshop` | |
| `spring.datasource.druid.password` | `******` | |
| `spring.redis.host` | `127.0.0.1` | |
| `spring.redis.port` | `6379` | |
| `spring.redis.password` | `******` | |
| `mshop.security.jwt-key` | 随机 48 字节 Base64 | **APP 端鉴权密钥，必须换掉默认值** |
| `jwt.base64-secret` | 随机 ≥88 位 Base64 | **管理端 HS512 密钥，必须换掉** |
| `jwt.secret` | 随机串 | 遗留字段，未被 TokenProvider 使用，但建议一并更换 |
| `rsa.private_key` | 自己的私钥 | 前端公钥需同步；不换等于密码明文传输 |
| `aes.encryptKey` | 自己的 16/24/32 字节 Key | **换掉会导致存量密文无法解密**，需评估 |
| `file.path` | `/home/mshop/file/` | 上传文件根目录，需有写权限 |
| `file.avatar` | `/home/mshop/avatar/` | 头像目录 |
| `quartz.main` | `true` | 多管理端部署时**只能有一个 true** |
| `jwt.token-validity-in-seconds` | `5760000000` | **命名有坑**：字段叫 `in-seconds`，但 `TokenProvider.java:63` 直接 `new Date(now + 值)`，`now` 是毫秒时间戳，所以实际单位是**毫秒**。`5760000000ms ≈ 66.7 天`。若按"秒"理解去填 `7200`，token 会在 7.2 秒后过期 |

#### 第三方平台（按需启用，用不到就留空）

| 配置前缀 | 用途 | 申请地址 |
| --- | --- | --- |
| `tb.*` | 淘宝联盟转链、订单 | 淘宝联盟 → 媒体合作 |
| `tb.pid.channelPid` / `tljPid` | **渠道推广位 PID** | 淘宝联盟后台创建，**必须换成自己的** |
| `jd.*` | 京东联盟 | union.jd.com |
| `pdd.*` | 拼多多联盟 | open.pinduoduo.com |
| `dataoke.*` | 大淘客（商品库、订单查询） | open.dataoke.com |
| `haodanku.*` | 好单库 CMS | www.haodanku.com |
| `meituan.*` | 美团外卖 CPS | union.dianping.com |
| `ele.*` | 饿了么 CPS | 淘宝联盟本地生活 |
| `wx.app.appId/secret` | 微信开放平台（APP 登录、支付） | open.weixin.qq.com |
| `aliyun.oss.file.*` | 阿里云 OSS（头像、证件） | oss.console.aliyun.com |
| `aliyun.sms.*` | 阿里云短信 | dysms.console.aliyun.com |

| `shop.contractUrl/sealUrl/licenseUrl` | 电子合同模板/公章/Aspose License | 自有 OSS |

#### 可选（不启用就关掉）

| 配置项 | 默认值 | 建议 |
| --- | --- | --- |
| `swagger.enabled` | `true` | **生产改 false**，否则接口文档全暴露 |
| `generator.enabled` | `true` | **生产改 false**，代码生成器不应对外 |
| `shop.convertContract` | `false` | 不做电子合同就保持 false（同时避免 Aspose 授权问题） |
| `single.login` | admin `false` / app `true` | 是否限制单用户登录 |
| `loginCode.enabled` | `false` | 管理端图形验证码，公网建议 `true` |
| `xss.enabled` | - | XSS 过滤开关 |

#### 需要留意的三个"假配置"

1. **`mshop.apiUrl`（admin 的 application.yml）**：代码里**没有** `@Value("${mshop.apiUrl}")` 读取它。分享海报、二维码的真实地址来自数据库 `system_config` 表的 `api_url` / `site_url`，需要在**管理后台 → 商城配置**里设置。改 yml 无效。
2. **`spring.redis.jedis.pool.*`（app 的 prod 配置）**：项目实际打包的是 `lettuce-core-6.1.10`（已验证 fat jar 内容），**jedis 池参数完全不生效**。要调连接池请改用：
   ```yaml
   spring:
     redis:
       lettuce:
         pool:
           max-active: 16
           max-idle: 8
           min-idle: 0
           max-wait: -1ms
   ```
3. **`mybatis-plus.global-config.db-config.mapper-locations`**：仓库内**没有任何 `*Mapper.xml`**（全部走 MyBatis-Plus 的 BaseMapper + 注解），该配置指向空目录，不影响运行。

## 五、构建

根目录 `lib/` 必须完整（`mshop-store` 与 `mshop-system` 共 8 个 `system` scope 依赖指向它）：

```
lib/
├── aspose-words-18.6.jar              # 商业库，电子合同用
├── jd-api-sdk-java-20250925.jar       # 京东联盟
├── meituan-union-java-1.0.jar         # 美团联盟
├── pop-sdk-1.25.54-all.jar            # 拼多多
├── taobao-sdk-java-auto_*.jar         # 淘宝联盟
├── taobao-sdk-ele.jar                 # 饿了么
├── yop-java-sdk-biz-4.3.3.jar         # 易宝支付
└── ysmp-java-sdk-core-1.0.jar         # 通联支付
```

> 如果 Maven 报「缺少 meituan-union-java / yop-java-sdk-biz」，按 `lib/README.md` 解压对应 zip 后重新 install。

### 5.1 标准构建命令

```bash
cd syh_server

# 只构建两个可运行应用及其依赖模块
mvn -pl mshop-admin,mshop-app -am package -DskipTests
```

**实测结果**（本机 JDK 17.0.11 + Maven 3.9.4）：

```
BUILD SUCCESS  —  58.5s
mshop-admin/target/mshop-admin-5.1.0.jar   157 MB
mshop-app/target/mshop-app-5.1.0.jar       159 MB
```

两个 jar 都已通过 `includeSystemScope=true` 把 `lib/` 下的第三方 SDK 打进 `BOOT-INF/lib/`，**目标机不需要再单独拷 jar 包**。

### 5.2 常见构建问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `ClassNotFoundException: ...classworlds...` | Git Bash 下的 `mvn` 是 Unix 脚本，classpath 未转 Windows 路径 | 用 `mvn.cmd`（Windows） |
| `inputFiles.lst: Input length = 1` | Maven 增量编译缓存损坏 | `rm -rf target/maven-status` 后重编 |
| 提示缺少第三方 SDK | `lib/` 不完整 | 补齐 `lib/`，或解压对应 zip |
| 编译报 `source option 8 is no longer supported（现使用 JDK 17，此错误仅见于旧配置）` | 用了 JDK 21+ | 换 JDK 17/11/17 |

## 六、启动

### 6.1 直接运行

```bash
# 管理服务（先起，定时任务在它里面）
java -jar mshop-admin/target/mshop-admin-5.1.0.jar \
     --spring.profiles.active=prod \
     -Xms512m -Xmx1536m \
     -Dfile.encoding=UTF-8

# APP 服务
java -jar mshop-app/target/mshop-app-5.1.0.jar \
     --spring.profiles.active=prod \
     -Xms512m -Xmx1024m \
     -Dfile.encoding=UTF-8
```

启动成功标志：

```
自研电商系统管理后台启动成功
官网：https://syh.hzhero.cn 提供技术支持
...
--------------------注入定时任务---------------------
--------------------定时任务注入完成---------------------
```

> 如果看不到「注入定时任务」，说明 `quartz_job` 表为空或连库失败。

### 6.2 systemd（推荐，Linux）

`/etc/systemd/system/syh-admin.service`：

```ini
[Unit]
Description=SFB Admin Service
After=network.target mysqld.service redis.service

[Service]
Type=simple
User=mshop
WorkingDirectory=/opt/syh
Environment="JAVA_HOME=/usr/local/jdk17"
Environment="MSHOP_JWT_KEY=替换为随机值"
ExecStart=/usr/local/jdk17/bin/java -Xms512m -Xmx1536m -Dfile.encoding=UTF-8 \
          -jar /opt/syh/mshop-admin-5.1.0.jar --spring.profiles.active=prod
Restart=on-failure
RestartSec=10
StandardOutput=append:/var/log/syh/admin.log
StandardError=append:/var/log/syh/admin.err

[Install]
WantedBy=multi-user.target
```

`syh-app.service` 同理，只改 jar 名与内存参数。

```bash
systemctl daemon-reload
systemctl enable --now syh-admin syh-app
systemctl status syh-admin
```

> **注意**：systemd 的 `Environment=` 只在服务内生效，若配置里用 `${MSHOP_JWT_KEY}` 占位，必须在这里注入。

### 6.3 Windows Server

```bat
@echo off
cd /d D:\syh
start "syh-admin" java -Xms512m -Xmx1536m -jar mshop-admin-5.1.0.jar --spring.profiles.active=prod
start "syh-app"   java -Xms512m -Xmx1024m -jar mshop-app-5.1.0.jar   --spring.profiles.active=prod
```

长期运行建议用 [WinSW](https://github.com/winsw/winsw) 注册成服务，配置与上面 systemd 等价。

> Windows 下 `file.path` 请用正斜杠或双反斜杠：`D:/syh/file/`。

## 七、Nginx 反向代理

```nginx
upstream syh_admin { server 127.0.0.1:8001; }
upstream syh_app   { server 127.0.0.1:8008; }

server {
    listen 443 ssl http2;
    server_name api.yourdomain.com;

    ssl_certificate     /etc/nginx/cert/fullchain.pem;
    ssl_certificate_key /etc/nginx/cert/privkey.pem;

    client_max_body_size 100m;      # 与 file.maxSize 保持一致

    # 管理端 API
    location /admin/ {
        proxy_pass http://syh_admin;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }

    # APP API
    location /api/ {
        proxy_pass http://syh_app;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    # 上传文件（对应 file.path / file.avatar）
    location /file/   { alias /home/mshop/file/;   expires 7d; }
    location /avatar/ { alias /home/mshop/avatar/; expires 7d; }

    # 生产环境屏蔽 Druid 监控与接口文档
    location ~ ^/admin/(druid|doc\.html|swagger-resources|v2/api-docs) {
        deny all;
    }
}
```

> **不要**在 Nginx 里再加一层 `proxy_pass http://.../admin`，因为应用本身已经有 `context-path: /admin`，会把路径变成 `/admin/admin`。上面的写法 `proxy_pass http://syh_admin;`（末尾无斜杠、无路径）表示原样透传，是正确的。

## 八、管理后台与 APP 对接

### 8.1 管理后台（syh_admin）

- 开发环境代理指向：`http://127.0.0.1:8001/admin`
- 生产环境把请求 baseURL 指向：`https://api.yourdomain.com/admin`
- 注意请求路径不要重复拼 `/admin`

### 8.2 APP（syh）

- 服务地址配置在 `lib/base.dart`，填**手机能访问到的**地址，例如 `https://api.yourdomain.com`
- 客户端会自动追加 `/api`
- 若走 HTTPS，确保 Android 端没有开启明文流量限制（`usesCleartextTraffic`）

### 8.3 必须去后台配置的两项

登录管理后台 → **商城配置 → 商城系统配置**：

| 配置 | 作用 | 示例 |
| --- | --- | --- |
| `api_url` | 分享海报、二维码里拼接的图片地址前缀 | `https://api.yourdomain.com` |
| `site_url` | H5 分享页地址 | `https://m.yourdomain.com` |

> 这两项不配，商品分享海报和推广二维码会生成失败（`StoreProductController:166` 会直接抛「请配置…」）。

## 九、定时任务说明

任务**不需要手工在 Quartz 里建**，由数据库 `quartz_job` 表驱动，启动时自动注册。

| 任务类 | 作用 | 建议频率 |
| --- | --- | --- |
| `TbOrderCollectionTask` | 淘宝订单实时采集 | 每 5~10 分钟 |
| `TbOrderHistoryCollectionTask` | 淘宝历史订单补采 | 每天 1 次（凌晨） |
| `JdOrderCollectionTask` | 京东订单采集 | 每 10 分钟 |
| `PddOrderCollectionTask` | 拼多多订单采集 | 每 10 分钟 |
| `VipOrderCollectionTask` | 唯品会订单采集 | 每 30 分钟 |
| `DyOrderCollectionTask` | 抖音订单采集 | 每 30 分钟 |
| `OrderMtCPSCollectionTask` | 美团 CPS 订单 | 每 30 分钟 |
| `FeeTriggerTask` | 当日预估佣金刷新 | 每小时 |
| `Fee7DayTask` / `FeeMonthTask` | 近 7 天 / 月度佣金统计 | 每天 |
| `BillUnlockTask` | 账单解锁（确认收货后可提现） | 每天 |
| `MemberExpiredTask` | 会员过期处理 | 每天 |
| `OrderRefundTask` | 退款订单处理 | 每小时 |
| `VisitsTask` | 访问统计 | 每小时 |

**多实例部署**：`quartz.main: true` 只在**一台**管理端设置。`quartz.full` 列表里的任务（订单采集类）只在该主节点执行，避免重复采集。

## 十一、故障排查

| 现象 | 排查方向 |
| --- | --- |
| 启动即退出，报数据源错误 | `spring.profiles.active` 是否指到了正确 profile；`xx.xx.32.56` 这类占位 IP 是否还留着 |
| 启动成功但接口 401 | `jwt.base64-secret` 与前端登录时使用的不一致；或 token 已过期（默认 `token-validity-in-seconds: 5760000000` ≈ 66 天） |
| APP 登录后立刻掉线 | app 端 `mshop.security.jwt-key` 被改过，旧 token 全部失效，属预期 |
| 订单一直是空的 | ① `quartz_job` 无数据 ② 采集任务未启用 ③ PID 不是自己的，被 `adZoneIds` 过滤掉了 ④ 联盟账号无订单权限 |
| 分享海报 500 | 后台 `api_url` 未配置；或 `file.path` 无写权限 |
| 后台很卡、Redis 超时 | 检查是否配了 `noeviction`；Redis 与 MySQL 是否同机争抢 IO；连接池实际走 lettuce，改 `spring.redis.lettuce.pool` |
| 图片/头像 404 | `file.path` / `file.avatar` 路径与实际挂载不一致；Nginx `alias` 末尾斜杠丢失 |
| 定时任务重复执行 | 多台管理端都设了 `quartz.main: true` |
| 电子合同转 PDF 带水印 | 未配置有效 Aspose License（`shop.licenseUrl`），或 `shop.convertContract` 误开 |
