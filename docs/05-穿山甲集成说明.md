## 二、部署步骤

### 1. 建表

```bash
mysql -u mshop -p mshop < docs/sql/mw_csj_reward_log.sql
```

验证：

```sql
SHOW CREATE TABLE mw_csj_reward_log;
-- 必须看到 UNIQUE KEY `uk_transaction_id`
```

> 这个唯一索引是防重放的核心，**不能省**。没有它，同一个奖励可以被反复领取。

### 2. 服务端配置

> **上线只需填 3 个配置项**（穿山甲激励视频属「广告变现」业务线，注册 + 资质认证 + 创建代码位即可自助开通，**无需商务审批**；与电商联盟 `csj-ecom` 的权限考核相互独立）：
>
> 1. `csj.enabled: true` —— 总开关
> 2. `csj.appId` —— 穿山甲后台创建应用后获得的应用 ID
> 3. `csj.rewardedVideoId` —— Android 激励视频代码位 ID（iOS 用 `csj.rewardedVideoIdIos`，不填则沿用 Android）
>
> 其余 `rewardIntegral` / `dailyLimit` / `minIntervalSeconds` 都有合理默认值，可不填。
>
> **入口显隐**：`enabled=false`（或上述任一必填项为空）时，`CsjConfig.isReady()` 为 false，`GET /csj/config` 只返回 `{"enabled":false}`；APP「我的」页据此**不渲染**「看视频赚积分」入口，`/csj/reward` 也会拒绝发奖。服务端启动时 `CsjConfig.logStatus()` 会打印配置状态，`appId` 只输出首尾各 4 位，不打印明文。

编辑 `mshop-app/src/main/resources/config/application-dev.yml`（生产改 `-prod.yml`）：

```yaml
csj:
  enabled: true                      # ← 改为 true
  appId: "5000000"                   # ← 穿山甲应用ID
  rewardedVideoId: "900000000"       # ← Android 激励视频代码位ID
  rewardedVideoIdIos: "900000001"    # ← iOS 代码位ID，留空则沿用 Android
  rewardIntegral: 10                 # 每次发多少积分
  dailyLimit: 5                      # 每人每天最多几次
  minIntervalSeconds: 30             # 两次之间最小间隔（秒）
```

**`enabled: false` 时**：`/csj/config` 返回 `enabled: false`，APP 页面显示「广告功能暂未开启」，`/csj/reward` 直接拒绝。

### 3. 重启服务端

```bash
# 重启 mshop-app（配置类在 store 模块，但接口在 app）
```

验证配置是否加载：

```bash
curl http://localhost:8008/api/csj/config
```

期望返回：

```json
{"code":200,"data":{"enabled":true,"appId":"5000000","rewardedVideoId":"900000000",
"rewardedVideoIdIos":"900000001","rewardIntegral":10,"dailyLimit":5}}
```

若 `enabled` 为 `false`，检查 yml 三件事：`enabled` 是否为 true、`appId` 是否为空、`rewardedVideoId` 是否为空（`CsjConfig.isReady()` 要求三者齐全）。

### 4. APP 依赖与构建

```bash
cd sfb
flutter pub get
flutter build apk --release
```

> 本机没有 Flutter SDK（无 `local.properties`），所以**APP 端代码未经过编译验证**，只按插件源码写了调用。首次构建如果报错，大概率是插件版本与 Flutter 版本不匹配，可尝试降到 `^2.6.1`。

### 5. iOS 额外配置（必须做，否则拿不到广告）

穿山甲要求 `Info.plist` 加 **SKAdNetworkItems**，这份列表会随 SDK 版本更新，**不要手抄**：

1. 登录穿山甲后台 → 应用 → 代码位 → iOS 配置
2. 下载官方提供的 `SKAdNetworkItems` 列表
3. 合并进 `ios/Runner/Info.plist` 的 `<dict>` 顶层

ATT 授权文案已经加好了：

```xml
<key>NSUserTrackingUsageDescription</key>
<string>我们需要您的授权，以便向您展示更相关的广告内容，不会影响您使用其他功能</string>
```

首次启动调 `requestIDFA` 才会弹出授权框（当前代码没有主动调，需要的话在 `CsjAdManager._ensureInit()` 里加 `await FlutterPangleAds.requestIDFA`）。

## 三、接口说明

### GET `/api/csj/config`（匿名）

返回客户端初始化所需配置，**不含任何密钥**。

```json
{
  "enabled": true,
  "appId": "5000000",
  "rewardedVideoId": "900000000",
  "rewardedVideoIdIos": "900000001",
  "rewardIntegral": 10,
  "dailyLimit": 5
}
```

### POST `/api/csj/reward`（需登录，Header 带 `Authorization: Bearer <token>`）

请求：

```json
{ "transactionId": "csj_1793282521400_a1b2c3", "posId": "900000000" }
```

成功：

```json
{ "success": true, "granted": 10, "integral": 10, "todayCount": 1, "dailyLimit": 5, "balance": 1240 }
```

失败（业务异常，`code` 非 200）：

| 提示 | 触发条件 |
| --- | --- |
| 广告功能未开启 | `csj.enabled=false` 或 appId/广告位为空 |
| 今日次数已用完 | 当天已达 `dailyLimit` |
| 操作过于频繁，请稍后再试 | 距上次奖励不足 `minIntervalSeconds` |
| 奖励流水号无效 | 同一 transactionId 被另一个 uid 用过 |
| 奖励已发放 | 并发重复提交（唯一索引兜底） |

## 四、流程与幂等设计

```
APP                         服务端                       数据库
 |                            |                            |
 |-- GET /csj/config -------->| 读 CsjConfig               |
 |<-- appId + 广告位 ---------|                            |
 |                            |                            |
 |-- 展示激励视频（SDK）       |                            |
 |   customData = txId        |                            |
 |                            |                            |
 |-- SDK onAdReward --------->|                            |
 |   (rewardVerify=true)      |                            |
 |                            |                            |
 |-- POST /csj/reward ------->| 1. 查 txId 是否已存在  --->|
 |   {transactionId: txId}    | 2. 查今日次数          --->|
 |                            | 3. 查上次奖励时间      --->|
 |                            | 4. insert 记录（唯一索引）->|
 |                            | 5. incIntegral（原子）  -->|
 |                            | 6. 写积分流水           -->|
 |<-- {granted, balance} -----|                            |
```

**幂等键**：`transactionId`。插件本身不提供奖励流水号（`AdRewardEvent` 只有 `rewardType`/`rewardVerify`/`customData` 等字段），所以由 APP 生成唯一 ID，通过 `customData` 传给 SDK，SDK 回调时原样带回。

**三层防刷**：

1. `transaction_id` 唯一索引 —— 同一笔只能发一次
2. 每日次数上限 —— 限制单账号收益
3. 最小间隔 —— 挡住脚本高频调用

## 五、安全局限（必须知道）

**当前实现防重放、防刷量，但防不住"被改造的客户端"。**

原因：`onAdReward` 是客户端回调，攻击者 hook 掉广告播放、直接伪造 `transactionId` 调 `/csj/reward`，服务端无法分辨。上面三层只能保证"同一个 ID 不会重复发"，挡不住"批量生成新 ID"。

**升级路径**（按性价比排序）：

1. **一次性 nonce**（成本低，建议做）
   - 新增 `GET /csj/token`（需登录）：服务端生成 UUID 存 Redis，5 分钟有效，绑定 uid
   - APP 用它作为 `customData`
   - `/csj/reward` 校验 Redis 中该 nonce 存在且属于当前 uid，然后删除
   - 效果：必须先合法登录拿 token，且每次只能用一次，刷量成本显著上升

2. **穿山甲服务端回调（S2S）**（最彻底）
   - 在穿山甲后台配置奖励回调 URL
   - 字节服务器直接回调你的接口，带签名
   - 服务端验签后发奖，完全不依赖客户端
   - 需要向穿山甲申请开通，并按其文档实现验签

3. **风控叠加**：同 IP/设备号频次、新用户首日限额、积分提现门槛联动
